# Беспроводной счётчик попаданий по стальному гонгу — объединённая архитектура (v3)

> Документ объединяет две проработки одной концепции: (A) практический прототип с приоритетом на минимум пайки/готовые модули/низкую цену, (B) более строгое ТЗ с упором на надёжность детектирования и радиопротокол. Ключевые архитектурные решения (радиомодуль, питание, метод детектирования удара) зафиксированы ниже как утверждённые.
>
> **v3:** зафиксирован дисплей (TM1637, 4 разряда), добавлена проверенная распиновка обоих узлов, пересмотрена частота heartbeat под реальный duty cycle LoRa, зафиксирован статус физической сборки на 14.09.2026.

## 1. Назначение

Автономная система, определяющая факт попадания в металлический гонг, передающая событие по радиоканалу на хост у стрелка и увеличивающая счётчик. Хост отображает счётчик, подаёт звуковой сигнал при новом попадании, индицирует состояние радиосвязи, имеет кнопку сброса.

Архитектура закладывает возможность развития до нескольких гонгов (TargetID в протоколе) и, в перспективе, определения места попадания по гонгу (TDOA, 3 датчика).

## 2. Принципы проектирования

- Минимум пайки — приоритет готовым модулям (dupont-соединения).
- Максимум готовых модулей вместо дискретных схем.
- Низкая стоимость (~15–20 USD за электронику комплекта, без учёта корпуса).
- Полевая надёжность важнее эстетики: зима, улица, вибрация от ударов.
- Один физический выстрел = одно событие счётчика, включая дробь и очередь.
- Протокол должен переживать повторную передачу пакета без задвоения счёта.

## 3. Архитектура узла-датчика (Sensor node)

- **МК:** ESP32-C3 dev-board.
- **Корпус:** сварной стальной куб/бокс, крепление к гонгу неодимовыми магнитами.
- **Механическая развязка:** электронная плата не должна быть жёстко закреплена на самой мишени — крепится через собственный кронштейн/демпфирующую подложку внутри корпуса; с гонгом механически связан только пьезоэлемент (короткий защищённый кабель).
- **Антенна:** внешняя SMA через bulkhead-разъём и просверленное отверстие — обход эффекта клетки Фарадея от стального корпуса.
- **Радиомодуль (утверждено): Ebyte E220-400T22D (LoRa, чип LLCC68, 433 МГц, UART, встроенный SMA-K).**
  - Подключение к ESP32-C3: VCC, GND, TX, RX + M0/M1 на GND (режим Normal). 4 dupont-провода + 2 на M0/M1, без пайки.
  - Диапазон 410.125–493.125 МГц (по умолчанию 433.125 МГц) — регуляторный контекст 433 МГц ISM/LPD433 в РФ; ограничения по duty cycle из п.7 применяются полностью.
  - Мощность 22 дБм (~158 мВт), заявленная дальность 5 км LOS — с запасом перекрывает требование 200 м.
  - Питание 3.3–5.5 В, TTL-уровни.
  - **Оба комплекта E220-400T22D в наличии, антенны физически подключены к обоим модулям (подтверждено).**
  - *Отклонённый вариант:* Ebyte E32-433T20D (SX1278) — заменён на E220-400T22D.
  - **Опция увеличения мощности:** старший вариант серии E220 с 30 дБм — рассмотреть только при нехватке дальности. Легальность на 433 МГц в РФ не проверена.
- **Питание (утверждено): 4×AA, литиевая химия (например, Energizer Ultimate Lithium).**
  - Вариант B (Li-Ion 18650 + USB-C) отклонён для текущей версии.

## 4. Детектирование удара (утверждено: Вариант A, с заделом на миграцию на Вариант B)

### Вариант A — LM393-компаратор + рефрактерный период (текущее решение, принято для MVP)

- Готовый модуль LM393 с внешним пьезодиском 20 мм, припаянным на контакты модуля (единственная неизбежная пайка проекта).
- Прошивка: единый рефрактерный период ~500 мс после срабатывания (значение предварительное — уточняется на этапе снятия осциллограмм реального удара, см. раздел 10, Этап 1).
- **Плюсы:** минимум пайки, простая прошивка, дешевизна, порог настраивается потенциометром на самом модуле.
- **Минусы:** не различает несколько попаданий в период звона гонга.

### Вариант B — прямой ADC + программный FSM-детектор (задел на будущее, не в MVP)

- Пьезодиск подключается напрямую к ADC-входу ESP32-C3 через минимальную защитную цепь.
- Прошивка реализует конечный автомат: `WAIT → IMPACT/RISING → PEAK/CONFIRM → RINGING → WAIT`.
- Признаки события: Peak, Energy, Rise Rate, Duration — все пороги калибруемые.
- Частота дискретизации для первой версии: 2–5 кГц.

**Решение:** MVP реализуется на Варианте A с возможностью миграции на Вариант B без переделки корпуса — пьезо на отдельном разъёме.

## 5. Архитектура узла-счётчика (Counter node)

- **МК:** ESP32-C3 dev-board.
- **Дисплей:** модуль TM1637, 4 разряда (подтверждено — физически на руках, вопрос TM1637 vs TM1638 снят).
- **Звуковая индикация:** пищалка (buzzer) — короткий сигнал при регистрации нового попадания.
- **Индикатор связи:** зелёный светодиод — см. п.6.
- **Кнопка RESET:** обнуление счётчика; защита от случайного нажатия (удержание 2+ секунды).
- **Радиомодуль:** Ebyte E220-400T22D, аналогично узлу-датчику.
- **Питание:** USB power bank.
- Все соединения — dupont, без пайки.

## 6. Индикатор связи (link status)

- Узел-датчик отправляет heartbeat-пакет раз в **2–3 секунды** (пересмотрено с исходных 200 мс/5 Гц — на LoRa такая частота давала бы ~20% занятости эфира и мешала бы прохождению hit-пакета).
- Узел-счётчик отслеживает время с момента последнего принятого heartbeat.
- Таймаут перехода «нет связи»: ~6–8 секунд (запас на пропуск одного-двух heartbeat).
- Пока время с последнего heartbeat меньше таймаута — зелёный светодиод горит, иначе гаснет.

## 7. Радиопротокол

Минимальный, устойчивый к повторной передаче протокол. Общая структура пакета:

```
MAGIC | TargetID | PacketType | EventNumber | Battery | Flags | CRC
```

- **TargetID** закладывается сразу, даже при одном гонге в первой версии.
- **PacketType** различает heartbeat-пакет и hit-событие.
- **EventNumber** — уникальный номер события попадания; хост игнорирует дубликаты, что исключает задвоение счёта при повторной передаче пакета.
- **Battery** — уровень заряда/напряжения узла-датчика.
- **CRC** — защита целостности пакета.
- **Duty cycle:** при пересмотренном heartbeat раз в 2–3 сек и типичном airtime пакета ~35–40 мс (SF7, BW125, короткий payload) занятость эфира — доли процента, что укладывается в норму ~1% duty cycle для 433 МГц ISM/LPD433 в РФ. Точные SF/BW параметры требуют финальной проверки перед полевыми испытаниями.

## 8. Логика хоста (узел-счётчик)

- При получении нового hit-события (по новому EventNumber) — увеличить счётчик на 1, кратко подать звуковой сигнал, обновить дисплей.
- Дублирующиеся EventNumber игнорируются.
- Зелёный LED управляется независимо, по heartbeat (см. п.6).
- Кнопка RESET обнуляет счётчик с защитой от случайного нажатия.

## 9. Распиновка ESP32-C3 (проверено, актуально на 14.09.2026)

Допущение: стандартная распиновка dev-board, номер GPIO совпадает с надписью на плате. Зарезервированы (не использовать): GPIO2/8/9 (strapping-пины), GPIO18/19 (встроенный USB), GPIO20/21 (UART0/Serial Monitor).

### Узел-счётчик (Host)

| Модуль | Контакт модуля | GPIO ESP32-C3 | Примечание |
|---|---|---|---|
| TM1637 | CLK | GPIO0 | — |
| TM1637 | DIO | GPIO1 | — |
| Buzzer | сигнал | GPIO3 | — |
| Кнопка RESET | сигнал | GPIO4 | `INPUT_PULLUP`, замыкание на GND |
| E220 | RXD | GPIO5 (TX ESP32) | крест: RXD модуля ← TX ESP32 |
| E220 | TXD | GPIO6 (RX ESP32) | крест: TXD модуля → RX ESP32 |
| E220 | AUX | GPIO7 | защита от коллизий при передаче |
| Link LED | анод (+) | GPIO10 | через резистор ~220–330 Ом |
| E220 | M0, M1 | GND напрямую | не МК-пин, режим Normal |
| E220 | VCC | 3V3 (см. предупреждение ниже) | — |

### Узел-датчик (Sensor)

| Модуль | Контакт модуля | GPIO ESP32-C3 | Примечание |
|---|---|---|---|
| LM393 | OUT (D0) | GPIO1 | `attachInterrupt` |
| E220 | RXD | GPIO5 (TX ESP32) | крест, как на хосте |
| E220 | TXD | GPIO6 (RX ESP32) | крест, как на хосте |
| E220 | AUX | GPIO7 | — |
| Батарея (опц.) | делитель напряжения | GPIO0 (ADC1_CH0) | номиналы делителя не подобраны — открытый вопрос |
| E220 | M0, M1 | GND напрямую | как на хосте |

**Предупреждение:** при передаче на 22 дБм E220 даёт бросок тока, который штатный стабилизатор dev-board может не выдержать (симптом — необъяснимые перезагрузки ESP32 во время передачи). При таких симптомах — конденсатор 100–470 мкФ рядом с VCC модуля.

## 10. Текущий статус сборки (на 14.09.2026)

- **Комплект «Счётчик»:** ESP32-C3 + TM1637 + buzzer + кнопка спаяны. Трансивер физически не установлен (был недоступен на момент пайки — учесть при монтаже под распиновку раздела 9). Залита тестовая прошивка: счётчик от 0, инкремент по нажатию кнопки, бип при срабатывании — заглушка для проверки дисплея/buzzer до готовности радио.
- **Комплект «Датчик»:** ESP32-C3 + LM393-компаратор + пьезодиск + E220-400T22D с подключённой антенной — собраны. Прошивка не залита.

## 11. Калибровка

- Сервисный режим (например, через USB Serial) для записи сырых данных: при Варианте B — сырые отсчёты ADC и вычисленные Peak/Energy/Rise Rate/Duration по каждому обнаруженному удару; при Варианте A — факт срабатывания и его временная метка.
- Порог пьезодатчика требует полевой калибровки, особенно для дроби на дистанции ~80 м.
- Для будущей 3-датчиковой локализации: фиксировать время прихода сигнала на каждый канал.

## 13. На горизонте (roadmap)

- Определение сектора/координаты попадания по TDOA при переходе на 3 пьезодатчика.
- Несколько гонгов на один хост через TargetID.
- Передача статистики на телефон/ПК (например, по BLE).
- Миграция детектирования удара на Вариант B, если потребуется надёжнее ловить очереди/дробь.
- Проверка легальности старшего варианта E220 (30 дБм) на 433 МГц в РФ.

## 14. Открытые вопросы

- Разработка прошивки: heartbeat, hit-детектирование, EventNumber/CRC-протокол, обновление дисплея/LED/buzzer — на обоих узлах ещё не реализовано (см. раздел 10).
- Итоговый рефрактерный период для Варианта A — зависит от осциллограмм реального удара (этап 1 плана).
- Точная настройка SF/BW для E220-400T22D под минимальный airtime heartbeat-пакета.
- Проверка легальности duty cycle для конкретного поддиапазона 433 МГц в РФ при пересмотренной частоте heartbeat.
- Номиналы резисторного делителя для замера напряжения батареи на GPIO0 узла-датчика.
